# 教师端、学生端与 QQ 的手工验收

本教程使用你自己有权使用的课件、课程和 QQ 测试群。源码包不包含雨课堂安装包、VSTO 安装包、注册表修复文件或个人 PPT。已正常使用的环境无需为测试重复安装。

## 准备

1. 在教师端准备一份含明确题干和选项的测试 PPT，保留原件并用副本测试。
2. 使用学生账号加入这门雨课堂课程，并在看板设置扫码登录该账号。
3. 保存支持图片的模型配置，通过文字和图片自检；真实调用可能产生模型费用。
4. 在看板为该课程新开一节并开始监听。
5. 如果要验收 QQ，先在设置中连接自己的机器人、绑定**专门测试群**，再在这门课程的“通知群”中选中它。

## 一次最小验收

| 步骤 | 操作 | 观察 |
| --- | --- | --- |
| 开课 | 教师在雨课堂插件里开课 | 看板从等待变为实时监听；选群后有一次上课通知 |
| 出题 | 推送一道新题 | 网页出现题面；QQ 先有新题提醒 |
| 解答 | 等待模型完成 | 网页和 QQ 显示答案、解析、可信度；未提供自评须明确显示 |
| 图片 | 检查图片投递 | Markdown 图片或明确记录的原生图片降级，不能把仅预览效果当作群显示成功 |
| 下课 | 教师端结束课堂 | 对应记录归档，选定群收到下课通知 |
| 回看 | 打开历史记录 | 只读查看，不自动重新作答或补发 |

测试不同新题时逐题核对题号。测试消息能到群，不表示每门课程自动选择了该群；在课程选群之前已收到的题不会追溯补发。

## 可选回归

- 暂停后继续同一记录：保留旧题并去重，后续新题继续入库。
- 刷新或关闭一个标签：其他打开的看板页面继续保活。
- 用“退出程序”正常退出再启动：课程、QQ 绑定和映射保留。
- 桌面模式关闭所有看板页面：3 分钟后退出，再双击可重启；命令行长期模式不适用此退出规则。

## 失败怎么分层检查

先看网页是否收题，再看模型是否作答，再看 QQ 是否生成投递记录，最后核对群里收到的内容。

“结果未知”必须先核对群消息，不要直接连续重试。反馈时只提供时间、阶段、状态和脱敏错误，不能公开 Key、Secret、登录信息或完整数据库。

真实验收只涵盖实际测试的账号、站点、群和客户端，不能推广为所有平台环境。不得用自动化测试向真实群批量发消息。
