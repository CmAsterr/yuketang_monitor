## 第一次使用：从启动到收题

### 1. 启动本机服务

Windows 推荐首次在项目目录中执行：

```powershell
python -m pip install -e .
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\install_desktop_shortcut.ps1
```

以后双击桌面的“雨课堂习题看板”即可：后台无黑框启动，就绪后打开浏览器。已有同一服务会复用，不会重复连接 QQ。

新启动的桌面服务采用网页保活：多个页面中只要还有一个连接就继续运行；关闭最后一个页面后宽限 3 分钟，然后停止课堂和 QQ 并退出。宽限期内重开页面可以继续使用。网页底部注明当前模式，“退出程序”用于立即正常退出整个服务。

如需关闭网页后仍长期运行，使用命令行：

```powershell
python -m yktmon serve
```

浏览器打开 `http://127.0.0.1:8787/`。命令行模式需要保持服务进程运行，直接关闭终端可能停止服务。快捷方式复用这种服务时，不会改变它的长期运行方式。

具体生命周期和重新安装快捷方式见 [桌面启动与后台运行](桌面启动与后台运行.md)。手工测试课件和安装材料的使用方法见 [本地课件与 QQ 手工测试](本地课件与QQ手工测试.md)。

### 2. 在“设置”中登录雨课堂

1. 选择正确站点，例如长江雨课堂。
2. 保存站点设置，点击“获取二维码”，用微信扫码。
3. 确认登录的是**已加入目标课程、能在学生端看到该课堂的账号**。
4. 查看是否显示“已登录”。

**老师已经创建课程，不代表当前学生账号已经加入。**教师侧新建的课程不会因为本地填了同名课程，就被程序自动搜到或加入。

可以先在雨课堂学生端核查这门课是否存在、是否处于上课状态。这只是人工检查；本程序收题不依赖打开雨课堂网页、浏览器插件或 Selenium。

> 程序连接实际课堂时会调用进入课堂／签到接口，可能产生签到记录。它不自动提交答案。

### 3. 配置多模态解答模型

在“设置 → 多模态解答模型”填写 API 地址和 API Key，获取模型列表，再选择支持图片的模型。

- 一个多模态模型直接看题面图并作答，不需要分别配置“识图模型”和“解答模型”。
- 获取到模型列表，只说明接口返回了这些名称，不代表每个模型都支持图片。
- 保存后点击“测试已保存的 AI 接入”，检查文字与图片识别两项结果。
- API Key 已保存后回填密码框，小眼睛切换显示／隐藏。
- 获取模型列表失败时可以手动填写服务实际支持的模型名。
- 模型接入失败不等于监听失败：题目仍可能已进入看板，只是没有生成答案。

### 4. 准备课程和本节记录

先看“课程管理”是否已有目标课程。程序会根据当前账号的正在上课列表发现课程，**不会保证列出账号全部未开课的课程**。

若已有“数据结构”，直接在它下面操作，不必再添加同名课程。也可以提前手动添加，但初始名称应与雨课堂返回的课程名一致；不知道课堂 ID 时不要随便填写。

1. 在“数据结构”右侧点击“新开一节”。
2. 给本节命名，例如“第 3 次课 · 栈与队列”。
3. 可以勾选“创建后开始监听”；不勾选时只是创建记录。
4. 创建后打开本节标签，需要时点击“开始监听”。
5. 等待显示“实时监听中”，老师推送的新题就会进入本节记录。

### 5. 需要群通知时再配置 QQ

只想在本机看题，可以跳过 QQ。

需要发群消息时，完成下文的“绑定 QQ 群”和“为课程选择通知群”。**建议在老师出题前完成课程选群**，旧题不会因为后来绑定通知群而自动补发。

## 课程、每节课和标签页分别是什么

### 三层关系

| 页面对象 | 作用 | 不会做什么 |
| --- | --- | --- |
| 课程，例如“数据结构” | 对应雨课堂中的课程身份，管理这门课的记录和 QQ 目标群 | 不会仅凭名称在雨课堂搜索、创建课程或加入课程 |
| 本节记录，例如“第 3 次课” | 保存本次监听收到的题面、解答和投递结果 | 不会在雨课堂教师端开课 |
| 顶部课堂标签 | 打开一份记录供查看或控制监听 | 打开标签本身不等于启动监听 |

例如：

```text
课程管理
└─ 数据结构
   ├─ 第 1 次课 · 线性表
   ├─ 第 2 次课 · 链表
   └─ 第 3 次课 · 栈与队列  ← 本次开始监听，题目存入这里
```

### 本地“新开一节”后，原来的雨课堂课程开课还能监听到吗？

**能，只要课程身份匹配，并且这份本地记录已开始监听。**

正常顺序是：学生账号已加入雨课堂中的“数据结构” → 本地选择“数据结构” → 新建“第 3 次课”并开始监听 → 老师在原课程开课 → 程序发现该账号能访问的课堂 → 建立实时连接 → 题目保存进“第 3 次课”。

本地新建记录时不会预先指定老师这次开课的编号。发现课堂后，程序才将远端本次课堂与选定的本地记录关联。

### 课程究竟如何匹配？

当前实现优先按**站点和雨课堂返回的课堂 ID（classroomId）**识别课程。未填写 ID 的手工条目，先按原始课程名建立规则；发现同名课堂时，有条件地补上真实 ID。

有三个名称／标识不要混淆：

- **原始课程名**：雨课堂返回的名字，手工提前建课时要匹配它。
- **自定义课程名**：点击“改名”后用于本地显示的别名，不改变原始课程身份。
- **本节课标题**：这份记录的名称，可以自由修改。

`classroomId` 是课程匹配使用的课堂身份；`lessonId` 是某次远端开课的身份。**不要把两者混填。**

如果站点选错、手工填错 ID，或雨课堂确实为课程返回了另一 ID，可能出现新条目或匹配不上。此时先检查课程身份，不要一味新建更多本地记录。同一站点存在多个同名课程时尤其应核实真实 ID。

### 修改名称会影响什么？

课程／课堂标题修改后，列表、标签和课堂页会同步更新，群消息预览和以后新生成的通知也使用新名称。

**已经发送的 QQ 消息不会被改名。已入队的消息保存了入队时的内容，也不会因改名自动重写或重发。**

## 上课、暂停、继续和下课

### “监听中”为什么还没有题目？

要区分“已要求监听”和“已经实际连接”：

| 显示 | 含义 | 下一步 |
| --- | --- | --- |
| 尚未开始 | 只创建了本地记录 | 点击“开始监听” |
| 监听中，同时提示等待开课或恢复连接 | 监听已开启，但可能还没找到老师的课堂，或正在重连 | 查看课堂动态、学生账号和网络 |
| 实时监听中 | 已收到课堂 WebSocket 握手确认 | 等老师推送题目 |
| 已暂停 | 本地停止收集，保留记录 | 点击“继续监听” |
| 已结束 | 记录已归档，默认只读 | 查看历史，或显式继续本节 |

顶部“0 节课已连接”表示没有实际课堂连接，并不代表所有本地监听意图都关闭了。判断是否真正接通，以该标签里的**课堂动态**为准。

### 发现间隔是 8 秒，为什么还说 WebSocket 实时监听？

“新课堂发现间隔”只用于查询老师是否开课。8 秒是一个配置示例，当前值以设置页为准。

建立课堂连接后，老师推题通过 WebSocket 接收，不是每 8 秒刷一次题目。发现失败和连接中断会按 1、2、5 秒等待重试，后续等待不再超过 5 秒；**这不是单次网络请求的超时上限，也不是群消息零延迟保证**。

### 暂停、结束、关闭标签有什么区别？

| 操作 | 课堂记录 | 后台收题 |
| --- | --- | --- |
| 切换到别的标签 | 保留 | 继续 |
| 关闭标签并选“后台继续并关闭” | 保留，可从课程列表重新打开 | 继续 |
| 暂停监听／暂停并关闭 | 保留，作为只读记录查看 | 该节停止 |
| 结束本节 | 归档；不会删除题目 | 该节停止 |
| 老师真正下课 | 对应记录归档 | 该课堂结束 |

暂停主要针对接收与作答任务；已经进入 QQ 投递队列的消息不因关闭课堂标签而自动撤回。若需阻止待发消息，到 QQ 投递记录取消尚未发送的任务，或停用对应群；发送中途取消可能留下“结果未知”。

### 课间暂停后还要继续，是否必须新开一节？

不必。想把前后内容放在同一份记录，就打开原记录并点“继续本节监听”；想分成两次记录，就先停止原记录，再“新开一节”。

同一门课程同时只能有一份本地记录接收题目；不同课程可以同时监听。重新连上同一远端课堂时，已保存的题目会去重，不会重新计数、重复生成或自动补发。

如果手动新建了一节，但老师实际仍在同一个远端课堂，之前已收到的题不会自动复制到新记录。后续新题才进入新选定的记录。

### 上课／下课 QQ 提醒何时触发？

对已经开启监听、并为课程选好通知群的课堂：

- 实际握手成功后发送“上课啦！”，不是创建本地记录时发送。
- 收到老师下课推送后发送“下课啦！”。如果未收到推送，当前实现还会以连续三次成功查询均已不在上课列表中作为结束判断。
- 查询失败不直接算下课；短暂断线重连不会重复发上课通知。
- 手动暂停或结束本地记录不冒充老师下课。

## QQ 绑定与课程通知群

### 两步都要做：先绑定群，再给课程选群

**机器人绑定某个 QQ 群，只代表程序知道这个群可作为通知目标；不代表所有课程都会自动发到它。**

首次设置：

1. 打开“设置 → 消息通知 → QQ 官方机器人”。
2. 填 AppID、AppSecret，启用通知并“保存并连接”。
3. 在 QQ 中将这只机器人加入目标群，并设置允许主动发言。
4. 页面点“添加群”，按页面指令在目标群内 @机器人并发送绑定码。
5. 回到页面确认候选群、填写别名并保存。事件没有群名时会显示候选编号，不代表绑定失败。
6. 回“课程管理”，在需要推送的那门课程右侧点“通知群”，勾选目标群并保存。

AppSecret 保存后可通过眼睛查看，QQ 配置与模型设置分开保存。绑定码是短期有效的；已经确认保存的群不会随绑定码过期而失效。

### 为什么测试消息能收到，课堂消息却收不到？

测试消息是你手工指定一个群发送，**不经过课程通知群的选择规则**。测试成功只能证明这次目标群和发送方式可用，不能证明每门课程都配好了目标。

举例：

- “数据结构”选了“学习群”，可以正常发消息。
- 新增“机器学习”，但没有给它选通知群。
- “机器学习”的题目可正常显示、正常作答，QQ群却不会收到。

解决：在“机器学习”右侧点“通知群”，选中“学习群”并保存。**无需重新加课程、无需新开一节、无需重绑机器人；下一道新题即可按新的配置发送。**

### 配完通知群，刚才那道题为什么没补发？

每道题在**首次被程序收到时**就固定了当时的 QQ 目标群。若那时未启用 QQ、未选群或群被停用，这道题不会因为后来改设置自动获得发送目标。

这个规则是“每道题一次”，不是“整节课只取一次”。所以当前课堂后续的新题会使用新保存的群映射，不需要刷新课堂页。

改群也不会把已入队的消息偷偷换到另一个群。手动重试既有投递使用原目标，不补造本来不存在的目标快照。

### 正常收到哪些内容？

上课提醒后，每道题通常依次出现：

1. **新题提醒**：课程、本节课、题号、中文题型，以及“大肥鱼正在做题喵～”。提醒不等待图片下载和模型作答。
2. **题面图片**：同一份课程信息与题号，便于对应题目。
3. **解答**：答案、解析、可信度。

图片和解答分开投递，单个发送失败不阻止另一个阶段。没有图片时，当前多模态作答流程可能也无法生成解答，会明确显示失败原因，不会假装回答成功。模型判断题目信息不足而返回空答案时，显示“无法作答”及理由，这是可读结果，不等同于接口故障。

题号从本节第 1 道收到的题开始计数；它不一定等于老师 PPT 的原始题号。网络、QQ 转存图片及模型响应会影响到达时间，不能保证绝对无延迟。

QQ 图片优先使用 Markdown 图片和加粗标题。图片地址不可用或请求被明确拒绝时可能降级为本地图片，投递记录会注明附文未加粗。QQ 客户端与网页的字体、换行和公式效果也可能略有区别。

### 如何看投递记录？

在“设置 → 消息通知 → QQ → 最近投递记录”展开查看，列表只显示最近 10 条，超出可在区域内滚动；更早的底层记录和去重凭据仍保留。题目卡片下也有对应 QQ 通知记录。

| 状态 | 含义 | 建议 |
| --- | --- | --- |
| 没有该题投递记录 | 该题可能首次收到时没有通知目标，或尚未进入该阶段 | 先核对课程选群与出题先后顺序 |
| 排队中 | 已有固定目标，等待发送 | 查看 QQ 连接状态 |
| 发送中 | 请求进行中 | 稍等，不连续点击测试或重试 |
| QQ 已返回消息 ID | 平台接口确认发送 | 在选定群里核对，不等于所有同学已读 |
| 失败 | 接口明确拒绝或处理失败 | 查看具体错误码、权限和内容提示 |
| 结果未知 | 请求可能已送达，但程序没拿到确认 | **先看群消息，再决定是否重试** |
| 已取消 | 待发任务被取消、群停用或切换机器人等 | 核对操作原因，不会自动重发 |

群状态“待验证”本身不是发送失败的结论。请结合实际投递结果和客户端收件判断。

“群消息预览”只预览当前模板，不会发送，也不会把旧 QQ 消息改成新格式。

## 怎么看习题与解答

- 原题图是主要题面，可点大图、下载，或从课堂页打开本机图片文件夹。
- 答案与解析支持 Markdown；网页公式使用 MathML 显示。
- 可信度是模型自评，不是经过统计校准的正确率保证。
- 模型没有返回自评时显示“未提供（模型未返回自评）”，程序不随意补一个百分比。
- 历史记录默认只读。显式继续本节后才开放重新作答等实时操作；不要为了单纯回看误开启监听。
- 模型处理失败与 QQ 发送失败分开：网页已经有答案但群里没有，优先检查投递；网页根本没有题，优先检查监听。

## 常见问题与排查顺序

### 问：教师端建了新课，本地也建了同名课，为什么一直等不到？

先检查**当前扫码账号是否已经以学生身份加入这门课**，并且能在雨课堂学生端看见正在上课的课堂。

程序查询的是已登录账号可访问的课堂列表，不是全平台按名字搜索。只在教师端建课、只在本地建同名规则，都不会完成学生加入动作。

先加入目标课程，再继续使用现有本地记录。仍找不到时，依次检查站点、原始课程名、课堂 ID、是否已开始监听，以及课堂发现错误提示。不要未经核对就认定一定是账号问题：网络超时或课程匹配异常也可能造成同样现象。

### 问：列表写着“监听中”，顶部却是 0 节已连接？

这通常表示你已开启本地监听，但还没建立实际课堂连接。看标签内的“课堂动态”：如果是等待开课或连接重试，先排查账号能否看到课程和网络。它不等于已经成功监听到题目。

### 问：同一门课突然出现两条，或者继续记录接不上？

先核对两条记录的站点、原始课程名和课堂 ID。自定义别名相同不表示 ID 相同。远端 ID 更换、手工填错 ID、存在同名课，都可能造成重复条目。

不要先删除带历史记录的条目。记录两边的 ID 和发生步骤，让维护者核对；当前程序不会自动把不同课程身份的历史合并。

### 问：网页有新题、有答案，QQ 没有？

按这个顺序查：

1. 这门课程的“通知群”是否选中并保存了正确群？另一门课的配置不会自动继承。
2. 是否在这道题首次收到**之前**完成启用和选群？之后保存不补发旧题。
3. QQ 是否已连接，群是否启用，机器人是否允许主动发言？
4. 有无该题的提醒、图片、解答投递记录？
5. 有失败则看具体原因，有“结果未知”先核对群消息。

更换或新增通知群后，用下一道真正的新题验证即可，不需要新建课程。

### 问：连不上或出现超时，要一直点开始吗？

不用反复点。程序有自动重连。先看当前错误发生在发现课堂、进入课堂还是实时连接阶段，并确认网络正常。只要已恢复“实时监听中”，旧的瞬时超时不代表现在仍断线。

### 问：老师没有下课，程序却归档了？

当前结束判断除老师推送外，还包含“连续三次成功查询都不在正在上课列表”。若远端列表临时不再包含这节课，也可能触发归档。

先在学生端确认仍在上课，再对原记录点“继续本节监听”。反复发生时，向维护者提供发生时间与课堂动态，不要靠大量新建记录绕过。

### 问：提示 QQ 试验网关还在运行？

旧直连试验页通常在 `8789`。先断开试验网关，再在正式 `8787` 设置中连接，避免同一机器人会话争抢。试验页的临时绑定不等于正式绑定；首次正式配置需保存并确认，之后不需要每日重做。

### 向维护者反馈时提供什么？

提供出错时间、使用的雨课堂站点、当前页面状态、课程与本节标题、是否已选通知群、网页是否已出现题目、投递阶段和错误信息即可。

不要在公开截图或仓库里提交 API Key、AppSecret、登录 Cookie、真实配置文件或包含凭据的数据库。

## 关网页、重启、换电脑会怎样

| 操作／情况 | 收题与发消息 | 是否需要重新绑定 QQ 群 |
| --- | --- | --- |
| 关闭网页／浏览器标签 | 桌面模式最后一个页面关闭 3 分钟后退出；命令行模式继续运行 | 不需要，重新启动同一数据目录即可 |
| 清空浏览器历史、缓存或网站存储 | 不删除服务端数据库；本地标签显示可能重置 | 不需要，从课程管理重新打开记录即可 |
| 暂停本节监听 | 停止该节收集；已排队消息不一定取消 | 不需要 |
| 关闭 8787 服务／停止 Python 进程 | 收题和 QQ 都停止 | 重新启动相同配置和数据目录后不需要 |
| 电脑关机或睡眠 | 无法保证持续收发；关机时停止 | 数据未丢失时不需要；唤醒／启动后检查服务 |
| 网络短断、QQ Token 到期 | 程序尝试自动恢复 | 通常不需要 |
| 雨课堂登录失效 | 重新扫雨课堂登录二维码 | 不需要，雨课堂登录与 QQ 绑定独立 |
| 点 QQ“断开” | 本次 QQ 收发停止，凭据和群保留 | 不需要，点“连接”即可 |
| 同一机器人重置 AppSecret | 保存新 Secret 后重新连接 | 一般不需要重新绑定原群 |
| 更换 AppID／另一只机器人 | 使用新的机器人身份 | 需要，旧群内部标识不能跨机器人使用 |
| 删除本地数据库，或换电脑不带原数据 | 原绑定和映射不可用 | 需恢复备份或重新配置 |
| 机器人被移出群或主动权限关闭 | 该群可能收不到消息 | 先加回／恢复权限；原关联失效时再重绑 |

**关闭课堂标签不等于关闭看板网页。**课堂标签只是网页内部的一页记录；仍有看板网页打开时，桌面服务继续保活。

**端口本身不是数据保存位置。**`8787` 是服务入口；绑定和课堂记录保存在本机数据目录。更改端口、清理浏览器，不等于删除数据库。

程序重启会恢复已保存的监听意图和 QQ 启用状态。若不希望重启后继续某节课，先在记录里暂停或结束；若不希望 QQ 自动连接，取消启用并保存。

默认重要文件：

- `config.toml`：模型与机器人配置等。
- `data/monitor.db`：课程、课堂记录、登录态、QQ 群绑定、课程群映射与投递队列。
- `data/images/`：本地题面图片。

路径可能通过启动参数改过，以启动信息显示的路径为准。备份这些文件时，最简单的方式是先停止服务再复制；运行中备份 SQLite 应使用专门的一致性备份方式，不能只拷贝主库而忽略 WAL 中的数据。备份含私人凭据，不要公开发布。

## 使用前快速检查

第一次配置后，日常上课前检查以下几项即可：

- [ ] 8787 看板可打开，本机服务在运行。
- [ ] 雨课堂站点正确，当前学生账号已加入目标课程且登录有效。
- [ ] 选择了正确课程和本节记录，并点了开始／继续监听。
- [ ] 老师开课后，“课堂动态”显示实时监听中。
- [ ] 需要解答时，模型已保存并通过图片自检。
- [ ] 需要 QQ 通知时，QQ 已连接、群已启用，而且**这门课程**已选择通知群。

老师还没出题时没有习题，是正常状态。出题后按“网页是否收题 → 是否生成答案 → 是否生成 QQ 投递 → 群内是否收到”的顺序检查，不要把四个不同环节混在一起。
